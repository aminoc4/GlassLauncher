# 回归测试报告（原生版）

测试时间：2026-11-23
测试环境：Windows 11 build 26300，2560×1440 @125%，8 核；w64devkit GCC 16.2（C++17）
被测程序：`dist/GlassLauncherNative.exe`（单文件、静态链接）

## 方法

- **内存口径**：`\Process(...)\Working Set - Private`（任务管理器"内存（专用工作集）"）；
  空载 = 启动后静置 15s、无拖动/无搜索。
- **拖动/帧率**：内置自动拖动钩子（`GL_NATIVE_AUTODRAG`），日志统计窗口移动 tick 与实时背景帧数。
- **吸附**：内置测试钩子（`GL_NATIVE_TEST_SNAP=left|right|top`），把光标放到目标边缘后走一次吸附判断。
- **截图排除**：`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`，用 GDI 抓屏做对照。
- **隐藏/显示**：向窗口投递 `WM_HOTKEY` 走完整的 `ShowLauncher/HideLauncher` 路径。

## 8 条硬性要求

| # | 要求 | 实测 | 结论 |
| --- | --- | --- | --- |
| 1 | 拖动全程可见、非模态 | 自动拖动 3 次：窗口移动 tick 95–96/1.5s（≈63–64 Hz），全程无 `WM_ENTERSIZEMOVE`；拖动中 hover/搜索仍响应 | 通过 |
| 2 | 拖动时背景实时流动 | 实时帧 56–59 帧/1.5s（≈37–40 fps），单帧抓取 16–17.6 ms；帧带抓取原点并按窗口位移对齐 | 通过 |
| 3 | 松手无闪、无透明缝 | 结束时丢弃在途实时帧 → 重新抓静态帧；实测整窗覆盖、无透明条（含缩放/最大化） | 通过 |
| 4 | 帧率≈60fps、UI 不卡 | 拖动 tick ≈64 Hz，背景 ≈40 fps；拖动整段 CPU ≈2–3%（8 核） | 通过（背景 40fps，窗口 60fps+） |
| 5 | 托盘 Hide/Show 反复不出问题 | 30 次循环：15 次 show / 15 次 hide，渲染正常、无异常；100 次循环句柄线性增长（见已知问题），内存稳定 | 通过（句柄有小幅系统级增长） |
| 6 | 内存 <60MB、空闲 CPU≈0 | 空闲私有工作集 **19.15 MB**；提交 ~75–90 MB；空闲 CPU ≈0%；拖动峰值 ~27–30 MB | 通过（远低于 60MB） |
| 7 | 用户截图看不到窗口 | 排除开启时抓屏，窗口区域显示的是背后桌面；关闭排除可正常截到窗口 | 通过 |
| 8 | 冷启动 <0.5s | `startup window-ready` 328–375 ms（最近 344 ms） | 通过 |

## 已知问题

1. **隐藏/显示的前台激活句柄增长**：本机 Win11 预览版上，每次真正的前台激活会新增约 10–25 个
   内核句柄（压力测试 100 次循环 ≈ +1.3k），但 6 分钟长稳测试里句柄稳定在 413–422、无持续增长；
   增长与"是否真正激活"相关，普通使用（偶尔唤出）影响可忽略。已 A/B 排除：分层窗口、
   DWM 圆角/边框属性、圆角区域、排除属性、搜索框聚焦、上传/抓屏路径；
   最小 D2D 探针无法被外部强制激活，无法复现。内存/CPU/渲染不受影响，标记为系统级行为待观察。
2. `Aero Snap` 目前只做左/右半屏与顶部最大化，不做四角 1/4 屏。
